# 当前系统界面与功能说明书

## 系统定位

当前系统围绕 BOM 交期风险排查展开，核心能力是把 BOM 项目、市场事件、行情信号、趋势预警和情报监控串成一条可追踪链路。用户可以从项目、事件、趋势或原始情报任一入口进入，查看事件来源、风险等级、触发条件和影响范围。

风险仪表盘当前保留现有页面，不作为本阶段主开发对象。后续可在市场事件、趋势预警和项目分析链路稳定后，再整理仪表盘的数据口径。

## 页面清单

### BOM 项目详情

入口：项目列表进入项目详情。

主要功能：

- 查看项目基本信息、物料清单和风险等级。
- 打开 HTML 风险报告。
- 下载 Excel 风险报告。
- 从物料行进入关联事件或风险分析结果。
- 从风险行动报告的行情证据直接在当前页打开统一市场事件详情。

本次修复：

- HTML 报告继续使用浏览器新窗口打开。
- Excel 报告改为稳定下载链路，避免新窗口拦截导致不可用。

### 市场事件

入口：主导航“市场事件”，也可由趋势预警、行情收件箱跳入。

主要功能：

- 查看市场事件列表。
- 按品牌、品类、事件类型、严重度、复核状态筛选。
- 查看事件详情。
- 查看事件影响项目。
- 查看行情收件箱复核来源。
- 打开信息源链接。

本次增强：

- “查看详情”改为分段容错加载。事件本体加载成功后立即打开详情；影响项目或复核来源加载失败时不阻断详情展示。
- 详情中增加风险等级、触发条件、来源链接、影响项目、复核来源。
- 触发条件展示严重度、置信度、交期影响和价格影响。
- 市场事件详情已抽成统一组件，后续趋势预警、行情收件箱、项目详情可以复用同一套详情展示。
- 支持 `/events?eventId=xx` 自动打开对应事件详情，其他页面跳转到市场事件后无需再手动查找。

### 行情收件箱

入口：主导航“行情收件箱”。

主要功能：

- 提交来自邮件、微信、官网、公告等渠道的市场通知。
- 从原始通知中抽取行情信号。
- 展示待复核队列。
- 对信号执行确认、驳回、观察。

本次增强：

- 待复核队列新增“查看溯源”。
- 溯源详情展示信号 ID、品牌、品类、型号、事件类型、置信度、复核状态。
- 展示原始通知标题、来源类型、来源名称和原文摘要。
- 如果信号已经生成市场事件，可在当前页打开统一市场事件详情，也可跳转到市场事件页面并定位事件。

### 趋势预警

入口：主导航“趋势预警”。

主要功能：

- 展示活跃事件、高风险事件、待复盘事件和主动预警行动。
- 聚合市场事件，提示需要关注的风险方向。
- 跳转到市场事件和影响项目。

本次增强：

- 主动预警行动展示触发条件。
- “查看事件”可在当前页打开统一市场事件详情。
- “前往事件库”跳转时携带首个事件 ID，可直接定位事件本身。
- 保留事件列表、项目列表、物料列表等关联查询参数。

### 情报监控

入口：主导航“情报监控”。

主要功能：

- 提交自然语言关注指令。
- 查看市场事件监控概况。
- 查看媒体源接入状态。
- 触发媒体源采集。
- 查看采集运行记录。
- 手动转发文章。
- 查看关注指令历史。

本次增强：

- 媒体源增加详情入口，展示源类型、状态、描述和配置字段。
- 采集运行记录增加详情入口，展示 source_id、状态、采集数量、生成事件数量、失败原因和时间。
- 关注指令历史增加详情入口，展示指令、抽取实体、建议行动和创建时间。

### 风险仪表盘

当前保留已有页面和能力，不继续扩展。

原因：

- 目前事件、趋势、收件箱、监控链路仍在补齐。
- 仪表盘需要稳定的数据口径，包括事件状态、影响范围、风险等级、通知状态和项目复盘状态。
- 等底层链路稳定后，再统一设计仪表盘展示逻辑更稳妥。

## 二三级链路说明

### 从行情收件箱到市场事件

1. 用户提交或导入原始通知。
2. 系统抽取行情信号。
3. 用户在待复核队列点击“查看溯源”。
4. 如果信号已确认并生成事件，点击“查看市场事件”。
5. 系统跳转到市场事件页面，并携带事件 ID。

### 从趋势预警到市场事件

1. 趋势预警聚合活跃事件、高风险事件和待复盘事件。
2. 用户点击行动队列中的“查看事件”。
3. 系统跳转到市场事件页面，并携带事件 ID、事件集合、项目集合和物料集合。
4. 市场事件页面读取 `eventId` 后自动打开对应事件详情。
5. 用户在市场事件详情中查看来源、触发条件和影响项目。

### 从市场事件到信息源

1. 用户打开市场事件详情。
2. 查看来源名称、来源类型和来源链接。
3. 点击来源链接打开原始信息。
4. 同时可查看行情收件箱复核来源和影响项目。

### 从情报监控到事件链路

1. 用户提交关注指令或配置媒体源。
2. 系统执行采集或手动转发文章。
3. 采集结果形成市场事件或行情信号。
4. 用户通过采集运行详情、关注指令详情理解事件来源。

## 市场事件、趋势预警、情报监控、行情收件箱的边界

### 市场事件

市场事件是事实中心。它保存已经结构化的外部市场变化，例如涨价、缺货、停产、交期延长、替代料变化等。其他模块最终都应能回到市场事件。

### 行情收件箱

行情收件箱是原始情报入口。它处理邮件、微信、官网公告、人工复制文本等未结构化或半结构化信息，并把它们转成待复核信号。

### 情报监控

情报监控是采集配置和运行状态入口。它负责关注指令、媒体源状态、采集任务、手动转发文章和采集运行记录。

### 趋势预警

趋势预警是分析和行动层。它不负责保存原始事实，而是把市场事件聚合成趋势、风险提示和建议动作。

## 是否存在功能重复

这几个模块确实有局部重叠，主要体现在：

- 市场事件和趋势预警都会展示事件。
- 情报监控和行情收件箱都会接触原始信息。
- 趋势预警和风险仪表盘未来都可能展示风险聚合结果。

这些重叠不是完全重复，而是因为它们处在同一条业务链路的不同阶段。当前更需要明确边界，而不是立刻合并页面。

## 整合建议

建议保留四个模块的职责，但未来可以把它们整合成“行情情报中心”：

1. 情报录入：承接行情收件箱能力，处理原始通知和待复核信号。
2. 事件库：承接市场事件能力，作为统一事实中心。
3. 趋势预警：承接聚合分析和行动建议。
4. 采集监控：承接情报监控能力，管理媒体源、关注指令和采集记录。

短期建议：

- 不调整主导航，先补齐链路和详情。
- 所有模块统一跳转到市场事件详情。
- 所有来源统一保留 source_url、source_name、source_type、raw_excerpt。
- 趋势预警只展示聚合判断，不保存重复事件正文。

中期建议：

- 把“市场事件详情”抽成可复用组件。
- 情行收件箱、趋势预警、项目详情都调用同一个事件详情组件。
- 建立统一的“来源详情”模型，兼容邮件、网页、微信、手动录入和 API 采集。

长期建议：

- 建立“行情情报中心”统一入口。
- 用事件事实库支撑风险仪表盘。
- 风险仪表盘只展示经过确认和影响分析后的聚合结果，避免展示未复核噪声。
