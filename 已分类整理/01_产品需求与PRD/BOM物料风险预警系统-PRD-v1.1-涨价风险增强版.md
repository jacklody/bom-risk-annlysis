# BOM物料风险预警系统 PRD v1.1：涨价风险增强版

> 更新日期：2026-06-24  
> 本版基于 v1.0 PRD、实施方案和用户上传的《分立器件供应商涨价对比：扬杰科技 vs 长晶科技》修订。  
> 本次修订重点：把“上游涨价/供应商调价通知”从附属信息升级为独立风险类型，纳入历史BOM巡检、新BOM评审和主动事件触发流程。

---

## 1. 文档关系说明

### 1.1 PRD 与实施方案的分工

| 文档 | 回答的问题 | 面向对象 | 典型内容 |
|------|------------|----------|----------|
| PRD | 要做什么、为什么做、做到什么程度 | 产品、研发、测试、业务负责人 | 用户场景、功能范围、页面逻辑、字段规则、验收标准 |
| 实施方案 | 怎么做、先做哪一步、用什么技术实现 | 技术负责人、开发人员、交付人员 | 架构设计、接口方案、数据库方案、开发阶段、风险和部署路径 |

PRD 是产品定义，实施方案是落地路径。PRD 先明确“涨价通知进入系统后应该产生什么风险提示和业务动作”，实施方案再定义“系统如何解析涨价函、如何匹配BOM、如何计算影响、如何触发告警”。两者应该保持同一套风险维度、字段名称和优先级。

### 1.2 本次优化结论

涨价因素应该加入系统，并且不应只作为“价格趋势”里的一个备注字段。它需要成为独立的风险事件类型：`price_increase`。原因是涨价通知具有明确的厂商、品类、涨幅、生效日期和应对窗口，能够直接驱动备货、替代、客户报价调整和项目成本复核。

## 2. 本次涨价通知如何在风险提示中体现

用户上传的涨价通知显示：扬杰科技、长晶科技在 2026年7月1日 前后对分立器件进行 10%–20% 调价，影响品类覆盖整流二极管、肖特基、TVS/ESD、稳压管、三极管、MOSFET、IGBT 等。系统识别后，应在每个命中的BOM物料上显示以下信息。

### 2.1 单颗物料风险提示

| 字段 | 示例 | 说明 |
|------|------|------|
| 风险类型 | 供应商涨价 | 由涨价函、公开资讯、邮件或人工录入触发 |
| 命中厂商 | 扬杰科技 / 长晶科技 | 通过品牌字段、MPN前缀、制造商别名匹配 |
| 命中品类 | TVS/ESD保护、二极管、MOSFET | 通过BOM品类、描述、规格文本匹配 |
| 涨幅区间 | 10%–20% | 支持区间和单值 |
| 生效日期 | 2026-07-01 | 用于判断紧急程度 |
| 剩余窗口 | 7天内 / 已生效 / 30天内 | 决定风险等级 |
| 预计成本影响 | 单颗成本 +0.012元；单板成本 +0.18元 | 基于当前单价、涨幅和用量估算 |
| 建议动作 | 7月1日前锁单；核查库存；开发第二供应商 | 给采购和项目经理使用 |
| 证据来源 | 用户上传涨价函 / 新闻链接 / 邮件附件 | 便于追溯 |

### 2.2 项目级风险提示

在项目详情页和风险报告中，系统应汇总：

| 汇总项 | 示例 |
|--------|------|
| 命中涨价物料数 | 42颗 |
| 涉及项目 | 历史项目A、项目B、新项目C |
| 涉及厂商 | 扬杰科技、长晶科技 |
| 涉及品类 | 二极管、TVS、MOSFET、三极管 |
| 单板成本影响 | 分立器件成本 +1.0%–1.5%，整机BOM +0.2%–0.6% |
| 紧急物料 | 生效日前7天内且无替代/库存不足的物料 |
| 建议动作 | 锁价、备货、替代评审、客户报价复核 |

### 2.3 风险等级规则

| 条件 | 风险等级 | 说明 |
|------|----------|------|
| 涨价已生效，且BOM中仍有未备货物料 | 红色 | 成本已经变化，应立即复核采购价和报价 |
| 生效日期≤7天，涨幅≥10%，命中关键项目或高用量物料 | 红色 | 需要立即锁单或替代 |
| 生效日期≤30天，涨幅≥10%，但库存充足或有替代 | 黄色 | 需要跟进采购策略 |
| 涨幅<10%或影响金额很小 | 绿色/灰色 | 仅记录趋势，不触发紧急动作 |
| 仅命中同品类但未命中厂商 | 黄色 | 作为行业波及风险提醒 |

## 3. 新增用户场景

### 场景D：收到供应商涨价函后主动触发风险识别

采购或供应链负责人收到一份扬杰/长晶涨价通知，希望系统立即判断历史BOM和新BOM中哪些物料受影响。用户上传 Markdown、PDF、图片、邮件正文或Excel涨价清单后，系统解析出厂商、品类、涨幅、生效日期和原因，再自动匹配所有历史BOM。

系统输出：

1. 命中的BOM项目和物料行。
2. 每颗物料的涨价风险等级。
3. 成本影响估算。
4. 生效日前的备货窗口。
5. 替代供应商和第二货源检查结果。
6. 需要采购、研发、项目经理分别处理的建议。

### 场景E：系统自动监控公开涨价信息并触发巡检

系统定时抓取或接入资讯源、供应商公告、邮件箱、飞书/企业微信群消息、分销商价格快照。当发现“涨价、调价、成本上涨、原材料涨价、晶圆代工涨价、封装材料涨价”等关键词，并识别出厂商和品类后，系统自动生成市场事件，再触发BOM命中分析。

| 涨价信息抽取 | 抽取厂商、产品线、品类、涨幅、生效日期、原因、证据来源 | P0 |
| 人工确认 | 抽取结果进入确认页，用户可修改厂商、品类、涨幅、生效日 | P0 |
| 生成风险事件 | 确认后写入 `MarketEvent` 或 `PriceIncreaseEvent` | P0 |
| 一键匹配历史BOM | 对所有历史BOM执行命中分析 | P0 |
| 一键匹配指定BOM | 对新上传BOM或指定项目执行分析 | P0 |
| 涨价事件看板 | 展示近30/90天涨价事件、命中项目和影响金额 | P1 |
| 事件关闭/归档 | 用户确认已处理后归档，保留证据和处理记录 | P1 |

### 4.2 新增模块：涨价风险识别

系统应按以下顺序匹配BOM：

1. 精确厂商匹配：BOM品牌为扬杰、YJ、Yangjie、长晶、CJ、Changjing 等。
2. MPN前缀匹配：通过品牌前缀和料号规则辅助判断品牌。
3. 品类匹配：二极管、TVS、ESD、MOSFET、BJT、IGBT、整流桥等。
4. 描述文本匹配：规格描述中出现肖特基、稳压管、ESD、TVS、快恢复、低压MOS等关键词。
5. 波及匹配：同品类但非同厂商，作为行业成本传导风险，不直接判为确定涨价。

### 4.3 新增模块：成本影响估算

估算逻辑：

```text
单颗涨价后价格 = 当前单价 × (1 + 涨幅)
单行BOM成本影响 = 当前单价 × 数量 × 涨幅
单板成本影响 = Σ 单行BOM成本影响
项目批量成本影响 = 单板成本影响 × 计划生产数量
```

如果只有涨幅区间，系统给出低/中/高三档估算：

```text
低位影响 = 当前单价 × 数量 × 最低涨幅
中位影响 = 当前单价 × 数量 × 区间中值
高位影响 = 当前单价 × 数量 × 最高涨幅
```

## 5. 主动触发与自动触发

### 5.1 主动触发

用户入口：`市场事件 → 上传涨价通知`。

处理流程：

```text
上传涨价通知
→ 系统解析文本/OCR
→ 抽取厂商、品类、涨幅、生效日期、原因
→ 用户确认或修正
→ 生成涨价事件
→ 选择分析范围：全部历史BOM / 指定项目 / 新上传BOM
→ 执行风险识别
→ 输出命中清单、成本影响和建议动作
```

### 5.2 自动触发

系统可从以下渠道自动获取：

| 渠道 | 可获取信息 | 实施优先级 |
|------|------------|------------|
| 供应商官网公告/新闻 | 官方调价通知、停产通知 | P1 |
| 邮箱监听 | 供应商涨价函、代理商通知 | P1 |
| 飞书/企业微信/钉钉群文件 | 销售或采购收到的涨价截图/文档 | P2 |
| 分销商价格快照 | 实际价格变化 | P0 |
| 用户手动上传 | 涨价函、Markdown、Excel、PDF、图片 | P0 |
| 行业资讯网页/RSS | 行业性涨价潮 | P2 |

自动触发规则：

```text
如果系统识别到“厂商 + 品类 + 涨幅/调价 + 生效日期”四类信息中的三类及以上，生成待确认事件。
如果缺少生效日期或涨幅，事件进入“待补充”状态，不直接触发红色风险。
如果事件来自用户上传且人工确认，直接触发BOM风险识别。
```

## 6. 风险评分算法补充

原PRD中的综合评分需要加入涨价维度。建议权重如下：

| 维度 | 权重 | 说明 |
|------|------|------|
| 交期风险 | 25% | 超过12周或交期大幅拉长 |
| 库存风险 | 20% | 零库存、低库存、单一渠道 |
| 生命周期风险 | 25% | EOL、NRND、Last Time Buy |
| 供应商集中度 | 10% | 单供应商或渠道不足 |
| 涨价风险 | 15% | 涨幅、生效窗口、命中范围和成本影响 |
| 通用性风险 | 5% | 非标准封装、非主流品牌、替代困难 |

涨价风险单独评分：

```python
def score_price_increase(increase_max_pct, days_to_effective, cost_delta_ratio, is_confirmed):
    score = 0
    if increase_max_pct >= 20:
        score += 35
    elif increase_max_pct >= 10:
        score += 25
    elif increase_max_pct >= 5:
        score += 10

    if days_to_effective is not None:
        if days_to_effective <= 0:
            score += 35
        elif days_to_effective <= 7:
            score += 30
        elif days_to_effective <= 30:
            score += 15

    if cost_delta_ratio >= 0.03:
        score += 20
    elif cost_delta_ratio >= 0.01:
        score += 10

    if is_confirmed:
        score += 10

    return min(score, 100)
```

判定规则：

| 得分 | 等级 |
|------|------|
| ≥70 | 红色 |
| 40–69 | 黄色 |
| 10–39 | 绿色 |
| <10 | 灰色 |

| 验收项 | 标准 |

## 9. 对当前开发版本的影响

现有 WorkBuddy 项目中已经有 `MarketEvent` 和 `BOMMatcher` 的事件匹配思路，因此涨价风险可以沿用“市场事件 → BOM匹配 → 风险评分”的框架，不需要推倒重写。需要补充的是：

1. `MarketEvent.event_type` 增加 `price_increase`。
2. 增加涨价事件结构化字段。
3. 在 `supply_risk.py` 中加入涨价风险评分。
4. 在前端风险表格增加涨价列。
5. 增加“上传涨价通知并触发分析”的入口。

这比单独开发一套涨价系统更稳妥，也能和交期、库存、EOL风险合并成统一风险结果。
