## 一、调研结论摘要

### 1.1 行业现状

- **电子元器件EOL加速**：2025年全球62.2万颗元器件停产，其中52%为"静默停产"（无任何PCN通知），仅25%的PCN符合JEDEC标准。
- **BOM管理方式落后**：国内78%的贸易商仍依赖Excel手工处理BOM清单。
- **AI+供应链正在快速渗透**：云汉芯城已接入DeepSeek-R1大模型，BOM秒级配单识别准确率超过90%。

### 1.2 核心发现

| 发现 | 影响 |
|------|------|
| 不能依赖制造商PCN做EOL监测 | 52%停产无通知，必须主动从分销商数据监控 |
| NRND是研发BOM的红线 | 出现NRND应立即替换，不能带入新项目 |
| 多源策略是安全底线 | 至少有2家供货渠道才算安全物料 |
| "交期>12周"+"EOL"覆盖80%+中断风险 | 优先抓这两个最大风险因子 |
| 数据积累是真正的护城河 | 自建优选库(AVL)长期价值远超一次性工具 |

### 1.3 方案选型决策矩阵

| 方案 | 适用场景 | 年成本 | 上线周期 | 定制化程度 | 数据自主性 |
|------|---------|--------|---------|-----------|-----------|
| **全自建**（Python开源栈） | 有研发团队、长期积累 | ¥0~2万（服务器） | 2-4周MVP | 极高 | 完全自主 |
| **半自建+商业API** | 中等团队、快速见效 | ¥2~10万 | 1-2周 | 高 | 核心数据自主 |
| **商业SaaS**（SiliconExpert/Z2Data） | 大规模企业、合规刚需 | ¥20~100万+ | 即用 | 低 | 受限于平台 |
| **国内平台**（云汉芯城/华秋） | 侧重国内采购、国产替代 | 0~¥5万 | 即用 | 中 | 受限于平台 |

> **推荐方案**：中小型硬件团队选择 **"半自建+商业API"** 路线，即自建核心引擎 + 调用LCSC/Mouser/DigiKey免费API + 按需接入云汉芯城替代推荐API。

### 2.3 大厂自建实践参考

华为、大疆等企业建立内部物料优选库(AVL)的典型模式：
- **统一物料编码** — 所有物料统一编号，消除型号歧义
- **多源认证** — 每个物料至少认证2家以上供应商
- **国产替代映射** — 关键海外物料提前建好国产替代映射表
- **多级审批流程** — 新物料引入需经过规格审查→交期审查→替代审查→商务审批
- **定期复审机制** — 每季度/半年对优选库进行全量复审

### 3.3 关键借鉴点总结

```python
# KiCost 的多源查询架构（简化）
distributors = [Mouser(), Digikey(), Farnell(), LCSC(), ...]
for part in bom:
    results = {}
    for dist in distributors:
        results[dist.name] = dist.query(part.mpn)  # 并发查询
    part.price = min(results.values(), key=lambda r: r.price)
    part.stock = sum(r.stock for r in results.values())

# bomer 的风险评分模型（简化）
def risk_score(part):
    score = 0
    if part.supplier_count == 1:      score += 0.4  # 单源风险
    if part.price is None:            score += 0.3  # 价格缺失
    if part.lifecycle == 'Obsolete':  score += 0.3  # 生命周期
    return score
```

### 4.2 核心功能详细设计

#### 功能一：历史BOM管理

| 子功能 | 描述 | 优先级 |
|--------|------|:-----:|
| **BOM归档** | 每个历史项目的BOM按版本存储，支持搜索和筛选 | P0 |
| **物料溯源** | 查看每颗物料在哪些历史项目中使用过 | P0 |
| **复用率分析** | 统计物料在不同项目中的复用频率 | P1 |
| **变更追踪** | 记录物料状态变化（Active→NRND→EOL），形成时间线 | P1 |
| **BOM对比** | 两个BOM版本之间的差异对比（增/删/改） | P2 |

#### 功能二：风险排查引擎

| 风险维度 | 检测逻辑 | 数据来源 | 告警阈值 |
|---------|---------|---------|---------|
| **交期风险** | 查询各渠道工厂交期 | Mouser/DigiKey API | >12周🔴 / 4-12周🟡 / <4周🟢 |
| **库存风险** | 汇总各渠道现货库存 | LCSC/Mouser/DigiKey | 总库存=0🔴 / 仅1渠道🟡 |
| **生命周期风险** | 检测Active/NRND/EOL状态 | 分销商API+制造商官网 | NRND🔴 / EOL=立即告警 |
| **供应商集中度** | 统计有现货的供应商数 | 所有渠道汇总 | 仅1家🔴 / 2-3家🟡 / ≥4家🟢 |
| **价格趋势** | 对比历史价格、检查涨幅 | 历史快照+实时查询 | 涨幅>30%🔴 / 10-30%🟡 |
| **通用性评分** | 是否标准封装+主流品牌+多货源 | MPN标准化+AVL比对 | 非标封装+单一货源🔴 |
| **出货量风险** | 物料是否大批量被采购 | 分销商库存变化趋势 | 库存急剧下降🔴 |

#### 功能三：定时监控与告警

| 子功能 | 描述 | 优先级 |
|--------|------|:-----:|
| **定时巡检** | 每周/每月自动对历史BOM全量物料重新查询 | P0 |
| **变化检测** | 对比上次查询结果，发现交期/库存/生命周期变化 | P0 |
| **智能告警** | 风险等级变化时自动通过邮件/企业微信/钉钉通知 | P1 |
| **风险仪表盘** | Web界面展示各项目风险物料统计和趋势 | P1 |
| **报告生成** | 定期生成风险报告（Excel/PDF），支持自动发送 | P2 |

#### 功能四：新BOM交期风险评审

| 子功能 | 描述 | 优先级 |
|--------|------|:-----:|
| **BOM上传解析** | 支持Excel/CSV上传，自动识别列名（型号/规格/封装/用量） | P0 |
| **型号标准化** | 提取核心MPN、去除包装后缀、模糊匹配纠错 | P0 |

| **P1** | Octopart/Nexar API | 400+分销商聚合 | 有免费层级 | GraphQL、一次查询多家 |
| **P2** | 云汉芯城API | 标准化SPU、国产替代 | 需商务 | 国产替代能力强 |
| **P2** | 制造商官网 | PCN/PDN通知 | 免费 | 需爬虫或RSS订阅 |

### 6.3 不要重复造轮子的部分

| 功能 | 建议方案 | 理由 |
|------|---------|------|
| **EDA集成** | 不自己做 → 调用KiCost/KiBot | 已有成熟开源方案，直接集成 |
| **参数搜索** | 用云汉芯城/LCSC的参数搜索 | 自建参数库成本极高 |
| **合规检查** | 用分销商API自带RoHS/REACH字段 | 合规数据变化快，自维护成本高 |
| **AI替代推荐** | 规则引擎为主 + LLM辅助校验 | 纯LLM易产生幻觉，规则引擎更可靠 |

## 七、风险评估与应对

### 7.1 系统建设风险

| 风险 | 概率 | 影响 | 应对措施 |
|------|:---:|:---:|---------|
| API数据源不稳定 | 中 | 高 | 多源冗余（至少3个API）+ 缓存层 + 降级策略 |
| 型号标准化准确率不足 | 中 | 中 | 先用规则引擎，积累纠错数据后引入ML |
| 数据积累周期长 | 高 | 低 | MVP阶段即可产出价值报告，逐步积累 |
| API调用频率限制 | 低 | 中 | 缓存+请求间隔控制+分批次查询 |
| BOM格式多样性解析失败 | 中 | 中 | 支持模板配置+自定义列映射 |

### 7.2 业务风险

| 风险 | 应对措施 |
|------|---------|
| 风险评分误报率高 | 允许用户手动标记误报，积累反馈优化阈值 |
| 替代型号推荐不准确 | 人工审核+确认机制，先做"候选推荐"而非"自动替换" |
| 团队推行阻力 | 先用免费工具快速产出价值（Excel报告），逐步引导到系统 |
