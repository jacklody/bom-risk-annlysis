# BOM物料风险预警系统 v3.0 优化建议
## 双轨预警策略与自进化机制

> 版本：v3.1 优化建议稿
> 日期：2026-06-25
> 基于：《BOM物料风险预警系统：上游组份网络与依据链方案 v3.0》评审反馈
> 核心升级：从单轨"材料传导链"升级为"材料传导 + 供需信号"双轨并行，叠加人工反馈自进化闭环

---

## 一、核心问题：为什么需要双轨策略

v3.0 的设计以"上游材料→器件"的成本传导链为核心逻辑。这对 PCB、连接器、继电器等**成本驱动型**品类是有效的——铜涨 10%，PCB 厂 1-3 个月内必然跟涨，传导链路清晰可量化。

但对 IC、功率器件、电源管理芯片等**供需驱动型**品类，材料传导链几乎失效：
- 硅片仅占 IC 制造成本约 5%，硅片涨价 10% 对 MCU 总成本影响不到 0.5%
- MCU 涨价、缺货的根本原因是 8 寸晶圆产能被车规/AI 挤占，不是硅片涨价
- 英飞凌功率器件涨价，驱动力是 IGBT 产能紧张 + 新能源车需求激增，与上游材料几乎无关

**结论：不能用同一套逻辑覆盖所有品类。需要分轨建模。**

### 2.2 第一轨：材料传导链（成本驱动型品类）

#### 适用品类与传导链路

| 传导链 | 可靠性 | 转嫁率 | 滞后时间 | 公开数据源 |
|--------|--------|--------|----------|-----------|
| LME铜价 → 覆铜板/铜箔 → PCB | **高** | 60-80% | 1-3个月 | LME实时行情 |
| LME银价 → AgSnO₂触点 → 继电器 | **高** | 30-50%（银触点类更高） | 2-4个月 | LME实时行情 |
| LME铜价 → 漆包线 → 电感/变压器 | **高** | 50-70% | 2-4个月 | LME实时行情 |
| LME铝价 → 阳极铝箔 → 铝电解电容 | **中高** | 40-60% | 3-6个月 | LME实时行情 |
| LME铜价 → 铜合金端子 → 连接器 | **中高** | 20-40% | 3-6个月 | LME实时行情 |
| 环氧树脂/双酚A → 覆铜板 → PCB | **中** | 含在覆铜板综合成本中 | 2-4个月 | 卓创资讯/百川盈孚 |

#### 关键参数：转嫁率与滞后时间

材料涨价 10% ≠ 器件涨价 10%。不同品类的"材料→器件"转嫁率和传导滞后差异巨大，必须建模：

```text
风险传导分 = 原材料价格变动幅度 × 转嫁率系数 × 时间衰减因子

其中：
- 转嫁率系数：材料成本占器件总成本的比例 × 供应商无法内部消化的比例
- 时间衰减因子：材料刚涨时影响最大，随时间推移供应商已消化或已传导则递减
```

#### 评分公式（成本驱动型品类）

```text
风险分 = 本体信号 × 0.20
       + 上游材料传导 × 0.30（需乘以转嫁率）
       + 供需平衡 × 0.15
       + 贸易政策 × 0.10
       + BOM影响面 × 0.15
       + 工艺产能 × 0.10
       - 缓冲因子（LTA锁价/安全库存）
```

### 2.3 第二轨：供需信号链（供需驱动型品类）

这是 v3.0 的核心缺失。IC 类物料的涨价/缺货，驱动力几乎不来自上游材料，而是来自供需失衡。

#### 当前市场行情实证（2026年6月）

| 品类/品牌 | 当前状态 | 涨价驱动因素 | 材料传导能解释？ |
|-----------|---------|-------------|----------------|
| 兆易创新 MCU | 涨价 + 缺货 | AI终端/汽车电子需求激增 + 8寸产能被挤占 | ❌ 与硅片价格无关 |
| MPS 电源IC | 涨价 | AI服务器对大电流电源需求爆发 + 产能紧张 | ❌ 与封装材料无关 |
| 圣邦微 模拟IC | 涨价 | 国产替代加速 + 需求增长 + 产能优先保高毛利品 | ❌ 与塑封料无关 |
| 英飞凌 功率器件 | 涨价10-20% | IGBT产能紧张 + 新能源车/光伏需求激增 | ❌ 与硅片/引线框架无关 |
| 华润微 分立器件 | 已执行第二轮10%+ | 晶圆代工涨价（这是成本驱动）+ 供需紧张 | ⚠️ 部分可解释 |
| TrendForce预测 DDR2 | Q2涨55-60%，Q3再涨35-40% | 产能转产DDR5导致DDR2供给收缩 | ❌ 纯粹的产能迁移驱动 |

**结论：上述案例中，仅华润微的分立器件涨价可以部分用材料传导解释，其余全部是供需驱动。单轨材料传导模型会漏报其中 80% 以上的风险。**

#### 供需信号链的六大信号源

| 信号类型 | 具体来源 | 信号强度 | 可获取性 | 时效性 |
|---------|---------|---------|---------|--------|
| **交期变化** | 供应商/分销商交期延长通知、采购端感知 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ 日常就能感知 | 最灵敏——交期先于涨价 1-3 个月 |
| **同行联动** | 同品类其他品牌已发涨价函 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ 你第一个收到涨价函 | 领先 0-1 个月 |
| **终端需求冲击** | AI服务器扩产、新能源车渗透率飙升、光伏装机量暴增 | ⭐⭐⭐⭐ | ⭐⭐⭐ 行业报告/新闻 | 领先 2-6 个月 |
| **产能迁移** | 某厂将产线从消费级转向AI/汽车级 → 消费级供给收缩 | ⭐⭐⭐⭐ | ⭐⭐ 行业信息/财报 | 领先 3-6 个月 |
| **晶圆厂产能利用率** | 台积电/中芯国际产能满载 → 全链条紧绷 | ⭐⭐⭐ | ⭐⭐ 财报+行业报告 | 领先 1-3 个月 |
| **分销商库存水位** | 艾睿/大联大/安富利库存天数下降 | ⭐⭐⭐⭐ | ⭐⭐ 部分可获取 | 领先 1-2 个月 |

#### 同行联动模型（核心创新点）

当一个品类的头部品牌已经涨价，系统应自动推演同品类/关联品类的风险：

```text
触发规则：
  品牌A（品类X）发布涨价函
  → 系统自动识别BOM中所有品类X的物料
  → 检查同品类其他品牌（B/C/D）是否处于高风险状态
  → 如果是，自动触发预警："同品类联动风险"
  → 预警等级 = 品牌A涨幅 × 联动系数

联动系数（根据历史经验设定，可自进化调整）：
  完全同品类竞品（如兆易创新→中微半导）：0.8-1.0
  同品类不同定位（如兆易创新MCU→国科微SSD控制）：0.4-0.6
  关联品类（如MCU涨价→配套PMIC需求增加）：0.3-0.5
```

**举例（当前行情）：**
- 英飞凌功率器件涨价 10-20% → 系统自动预警 BOM 中的华润微、捷捷微电、士兰微功率器件也面临涨价压力
- 兆易创新 MCU 涨价 + 缺货 → 系统自动预警 BOM 中其他 MCU 品牌（中微半导、国民技术等）
- MPS PMIC 涨价 → 系统自动预警圣邦微、芯朋微等国产 PMIC 品牌

#### 评分公式（供需驱动型品类）

```text
风险分 = 本体信号 × 0.25
       + 供需平衡 × 0.25（交期变化 + 库存水位 + 产能利用率）
       + 同行联动 × 0.15（同品类品牌涨价联动）
       + 终端需求冲击 × 0.10（AI/汽车/新能源需求信号）
       + 工艺产能 × 0.10
       + 贸易政策 × 0.10
       + BOM影响面 × 0.05
       - 缓冲因子（LTA锁价/安全库存）
  
注意：上游材料传导权重降至 < 5%（因材料成本占比极低）
```

## 三、自进化机制：系统如何越用越准

### 3.1 核心理念

系统不可能一开始就覆盖所有风险场景。关键不是"第一次就做对"，而是"错了能学会"。

马工的实际需求场景：
> "现在是行情就是MCU兆易创新肯定涨价还缺货，MPS、圣邦微电源类也在涨，英飞凌功率器件也在涨。如果涨了系统没有预警，我人工触发给系统，系统要能自我进化，越来越查得准报的对。"

这本质上是一个 **Human-in-the-Loop 增量学习系统**。

### 3.2 自进化闭环架构

```text
┌─────────────────────────────────────────────────────────────────────┐
│                        自进化闭环                                     │
│                                                                       │
│  ① 预警触发（双通道）                                                 │
│     ┌──────────────┐    ┌──────────────┐                              │
│     │  系统自动预警  │    │  人工手动触发  │ ← 马工发现行情变了但       │
│     │  （行情/涨价函）│    │  （经验判断）  │    系统没报，手动录入       │
│     └──────┬───────┘    └──────┬───────┘                              │
│            │                    │                                      │
│            └────────┬───────────┘                                      │
│                     ↓                                                   │
│  ② 事件记录（结构化）                                                  │
│     · 哪个品类？哪个供应商？哪个品牌？                                  │
│     · 什么信号触发的？（涨价函/交期延长/缺货/同行联动）                 │
│     · 当前市场状态描述                                                  │
│     · 关联品类标注（"这个涨了，XX品类可能也会跟"）                      │
│                     ↓                                                   │
│  ③ 事后验证（自动 + 人工）                                             │
│     · 30天/60天后自动回查：这个供应商这个品类，价格实际涨了吗？          │
│     · 涨了 → 预警准确，强化该信号规则                                  │
│     · 没涨 → 预警偏差，降低权重或标记为噪声                            │
│     · 涨了但系统没报 → 漏报，需要补充新的信号规则                      │
│                     ↓                                                   │
│  ④ 规则迭代（权重自调）                                                │
│     · 每条预警规则有一个"可信度分数"（初始 0.5）                        │
│     · 验证准确：可信度 +0.1（上限 1.0）                                │
│     · 验证偏差：可信度 -0.1（下限 0.1）                                │
│     · 可信度 > 0.7 的规则自动升级为"强规则"（权重×1.2）               │
│     · 可信度 < 0.3 的规则自动降级为"弱规则"（权重×0.5）               │
│                     ↓                                                   │
│  ⑤ 联动推演（自动扩展）                                                │
│     · 人工录入"兆易创新MCU涨价"时标注关联品类：                        │
│       - 同品类MCU品牌（中微半导、国民技术）→ 联动系数0.8              │
│       - 配套PMIC（MPS、圣邦微）→ 联动系数0.4                          │
│     · 下次系统检测到兆易创新涨价信号，自动推演关联品类的风险            │
│     · 推演结果如果事后验证准确，联动系数自动上调                       │
│                                                                       │
│  ⑥ 知识沉淀（长期进化）                                                │
│     · 积累足够的"预警→验证"数据后，系统形成每个品类的"风险画像"        │
│     · MCU品类的风险画像：对交期变化极敏感、与晶圆产能利用率强相关、     │
│       同行联动系数高、与上游材料几乎无关                                │
│     · PCB品类的风险画像：与铜价强相关、传导滞后约2个月、转嫁率约70%    │
│     · 这些画像随使用越来越精确                                          │
└─────────────────────────────────────────────────────────────────────┘
```

### 3.3 人工触发预警的操作流程

```text
马工操作界面：

┌─────────────────────────────────────────────────────┐
│  📢 手动录入预警事件                                  │
│                                                       │
│  品类：[MCU              ▼]                           │
│  供应商/品牌：[兆易创新    ▼]                          │
│  信号类型：                                           │
│    ☑ 涨价（涨幅：[15]%）                              │
│    ☑ 缺货（状态：[严重缺货 ▼]）                       │
│    □ 交期延长（从 [4] 周延长到 [12] 周）              │
│    □ 产能紧张（描述：________）                       │
│                                                       │
│  关联品类推演（系统根据历史数据建议，人工确认）：       │
│    ☑ 同品类MCU品牌 → 联动系数 [0.8]                   │
│    ☑ 配套PMIC → 联动系数 [0.4]                        │
│    ☑ 配套存储DDR → 联动系数 [0.3]                     │
│    □ 其他：[________] 联动系数 [___]                  │
│                                                       │
│  信息来源：[□ 涨价函  □ 分销商通知  □ 行业消息         │
│            □ 自主判断]                                 │
│                                                       │
│  备注：[AI终端需求激增，8寸产能被车规挤占，           │
│        短期内看不到缓解迹象]                           │
│                                                       │
│                          [取消]  [提交预警]            │
└─────────────────────────────────────────────────────┘
```

**提交后系统自动执行：**
1. 记录本次预警事件（品类、供应商、信号、关联品类）
2. 立即触发关联品类的联动预警
3. 创建"验证任务"：60天后自动回查该品类是否确实涨价
4. 如果是新规则（之前没见过的信号组合），标记为"待验证规则"
5. 更新该品类的风险画像数据

### 3.4 验证闭环的数据结构

```text
预警记录表（alert_records）：
  id              - 预警ID
  date            - 预警日期
  source          - 来源（auto=系统自动 / manual=人工触发）
  category        - 品类（MCU/PMIC/Power/PCB/...）
  supplier        - 供应商/品牌
  signal_type     - 信号类型（price_up/shortage/lead_time/capacity）
  signal_detail   - 信号详情（涨幅/缺货程度/交期变化等）
  predicted_risk  - 预测风险等级
  linked_categories - 关联品类及联动系数（JSON）
  verified        - 是否已验证（0=待验证/1=已验证准确/2=已验证偏差）
  verify_date     - 验证日期
  verify_result   - 验证结果描述

规则权重表（rule_weights）：
  id              - 规则ID
  category        - 适用品类
  signal_pattern  - 信号模式描述
  credibility     - 可信度分数（0.1-1.0，初始0.5）
  hit_count       - 命中次数
  accuracy_count  - 准确次数
  last_updated    - 最后更新时间
```

## 四、传导链可靠性分级

不同品类的风险信号可靠度差异巨大，不能一刀切。分三级管理：

| 可靠性等级 | 定义 | 适用场景 | 评分权重影响 |
|-----------|------|----------|-------------|
| **已验证传导** | 有涨价函、行业报告或历史数据直接证实的传导关系 | 铜→PCB、银→继电器、铝→铝电解、同行联动（已验证） | 权重 × 1.0 |
| **理论传导** | 基于材料成本占比推断，逻辑成立但缺乏直接证据 | 环氧树脂→覆铜板、晶圆代工价格→IC成本 | 权重 × 0.5 |
| **弱关联** | 间接关联或占比极低，传导概率不高 | 硅片→IC成本、玻纤布→连接器 | 权重 × 0.2 |

## 五、"信息不足"状态
