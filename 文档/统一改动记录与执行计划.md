## CR-001 风险链路驾驶舱与上游组成库打通

### 需求背景

当前系统中，“元器件上游组成库”与“风险链路驾驶舱”已经存在概念关联，但两者还没有完全形成稳定的数据闭环。上游组成库偏静态映射，风险链路驾驶舱偏图谱展示和项目风险表达。后续需要将两者明确打通，使驾驶舱展示的影响链路来自真实映射、市场事件和当前 BOM 匹配结果，而不是模板化展示。

### 目标链路

需要记录并实现如下风险传导路径：

```text
市场事件：铜价上涨
  ↓
命中材料：铜箔 / 铜合金
  ↓
上游组成库反查：PCB / 连接器 / 线束
  ↓
当前BOM匹配：哪些PCB、连接器、线束物料
  ↓
驾驶舱展示：影响路径、风险等级、建议动作
```

### 产品目标

1. 市场事件不再只停留在“事件列表”，而是能向下传导到材料、品类和 BOM 物料。
2. 元器件上游组成库不只作为资料展示，还要成为风险链路推导的基础数据。
3. 风险链路驾驶舱中的“物料组分、影响链路”应能解释每条路径的来源。
4. 用户看到一条风险链路时，应能知道：
   - 是哪个市场事件触发的；
   - 命中了哪些上游材料；
   - 这些材料影响哪些元器件品类；
   - 当前 BOM 中有哪些物料被影响；
   - 系统为什么给出这个风险等级和建议动作。

### 当前问题

| 问题 | 说明 | 影响 |
|---|---|---|
| 上游组成库与驾驶舱口径不完全一致 | 驾驶舱只取部分材料，且可能存在模板兜底 | 用户难以判断链路是否来自真实数据 |
| 市场事件到材料的命中规则不清晰 | 事件标题或内容中的“铜价上涨”如何命中“铜箔/铜合金”尚未清晰展示 | 风险链路可信度不足 |
| 材料到元器件品类的反查未显式展示 | 上游组成库里有映射，但驾驶舱没有清楚说明反查过程 | 用户不知道 PCB/连接器为什么受影响 |
| BOM 匹配结果缺少解释 | 当前 BOM 哪些物料被命中，需要明确展示 | 难以指导采购和项目排产 |
| 建议动作需要基于证据来源 | 建议不能泛泛而谈，需要对应事件、材料和 BOM 影响 | 降低误判和过度预警 |

### 改动方案

#### 1. 数据链路改造

将风险链路推导拆成五层：

| 层级 | 数据对象 | 说明 |
|---|---|---|
| L1 市场事件 | MarketEvent | 缺货、涨价、交期、EOL、政策、灾害等结构化事件 |
| L2 上游材料 | upstream_materials | 铜箔、铜合金、树脂、钛酸钡、镍粉等 |
| L3 元器件品类 | component_category | PCB、连接器、线束、MLCC、MCU 等 |
| L4 BOM 物料 | bom_items | 当前项目 BOM 中的实际物料行 |
| L5 风险输出 | risk_path / suggestion | 影响路径、风险等级、建议动作 |

#### 2. 命中规则

市场事件需要通过关键词、品牌、品类、材料别名命中上游材料。例如：

| 市场事件内容 | 命中材料 | 命中理由 |
|---|---|---|
| 铜价上涨 | 铜箔、铜合金 | 事件关键词命中材料别名“铜” |
| 环氧树脂供应紧张 | 环氧树脂 | 材料名称直接命中 |
| MLCC 原材料涨价 | 钛酸钡、镍粉、陶瓷粉体 | 通过 MLCC 品类反推关键材料 |
| 金价上涨 | 金盐、镀金端子相关材料 | 贵金属材料命中 |

命中结果需要记录证据来源，不能只输出结论。

#### 3. 上游组成库反查

上游组成库需要支持两类查询：

```text
元器件品类 → 上游材料
上游材料 → 受影响元器件品类
```

示例：

```text
铜箔 → PCB
铜合金 → 连接器 / 线束
环氧树脂 → PCB / 封装材料
钛酸钡 → MLCC
镍粉 → MLCC / 电池相关材料
```

#### 4. 当前 BOM 匹配

系统根据反查得到的元器件品类，在当前 BOM 中查找对应物料：

| 反查品类 | BOM 匹配字段 | 示例 |
|---|---|---|
| PCB | raw_category / normalized_category / description | PCB板、线路板、FPC |
| 连接器 | category / part description | Connector、接插件、端子 |
| 线束 | category / description | Cable、Harness、线束 |
| MLCC | category / spec | MLCC、电容、陶瓷电容 |

匹配结果要输出：

- BOM 行号；
- 型号；
- 品牌；
- 品类；
- 命中原因；
- 对应风险路径。

#### 5. 驾驶舱展示调整

风险链路驾驶舱中，影响链路建议展示为：

```text
铜价上涨
  → 铜箔 / 铜合金
  → PCB / 连接器 / 线束
  → BOM命中物料：X条
  → 风险等级：关注 / 较高 / 高风险
  → 建议动作：确认库存、供应商报价、替代料、排产缓冲
```

每条链路应支持展开查看：

| 展示项 | 内容 |
|---|---|
| 触发事件 | 事件标题、来源、时间、置信度 |
| 命中材料 | 材料名称、命中关键词、材料别名 |
| 影响品类 | 从上游组成库反查出的品类 |
| BOM 命中物料 | 行号、型号、品牌、当前风险等级 |
| 建议动作 | 采购、研发、项目排产建议 |

### 风险等级建议规则

初版建议采用证据分层，避免泛化风险一票否决。

| 风险等级 | 触发条件 |
|---|---|
| 高风险 | 明确事件 + 明确材料命中 + BOM 物料命中 + 供应数据异常或 EOL/停产证据 |
| 较高风险 | 明确事件 + 材料命中 + BOM 物料命中，但供应数据尚未确认 |
| 关注 | 行业/材料级事件命中，但未直接命中品牌、型号或当前 BOM 关键料 |
| 数据待确认 | 仅存在弱关键词命中，无明确材料或 BOM 命中证据 |

### 验收标准

| 验收项 | 判断标准 |
|---|---|
| 市场事件能命中材料 | 输入“铜价上涨”类事件后，系统能识别铜箔/铜合金等材料 |
| 材料能反查品类 | 铜箔能反查 PCB，铜合金能反查连接器/线束 |
| 品类能匹配当前 BOM | 当前 BOM 中对应 PCB/连接器/线束物料能被列出 |
| 驾驶舱能展示完整链路 | 页面展示“事件 → 材料 → 品类 → BOM物料 → 建议” |
| 风险等级有证据 | 高风险必须有明确硬证据，弱证据只能给关注或待确认 |
| 来源可追溯 | 每条链路能看到触发事件和上游组成库来源 |
| 旧模板不误导 | 没有真实命中时，不展示为已影响当前 BOM |

### 执行计划

#### 阶段 1：梳理现有数据结构

- 检查 `industry_chain_library.py` 中元器件品类和上游材料结构。
- 检查 `risk_chain.py` 中驾驶舱图谱生成逻辑。
- 检查 `MarketEvent` 事件字段是否足够表达材料命中。
- 输出当前数据差异点。

#### 阶段 2：补充材料命中与反查能力

- 增加材料别名和关键词映射。
- 增加“事件 → 材料”的命中函数。
- 增加“材料 → 元器件品类”的反查函数。
- 增加单元测试：铜价上涨、环氧树脂紧张、钛酸钡涨价等样例。

#### 阶段 3：打通 BOM 匹配

- 使用当前 BOM 的标准化品类和描述字段匹配反查品类。
- 输出被影响 BOM 行。
- 给每个 BOM 命中项生成命中原因。
- 增加测试：材料事件应只影响相关 BOM 物料，不能全量泛化。

#### 阶段 4：改造风险链路驾驶舱展示

- 将图谱节点改为真实链路：事件、材料、品类、BOM 物料、建议动作。
- 每条链路支持展开查看证据。
- 区分“真实命中”和“知识库推测”。
- 没有 BOM 命中时显示“未命中当前 BOM”，不显示为项目风险。

#### 阶段 5：回归与验收

- 运行后端链路推导测试。
- 运行前端驾驶舱测试。
- 使用样例事件“铜价上涨”验证完整路径。
- 使用一个不相关事件验证不会误伤全 BOM。
- 构建前端并检查产物文案。
